# Frontend build dependency migration

Tailwind CSS and its official PostCSS plugin are pinned to 4.3.3, with tailwind-merge 3.7.0 for v4 utility compatibility. The former Tailwind 3 build dependency chain containing braces, Chokidar, Micromatch and fast-glob is removed. Full development-inclusive audit is required; runtime-only audit is a separate check, not a substitute. No advisory suppression or dependency override was introduced.

The [official upgrade guide](https://tailwindcss.com/docs/upgrade-guide) moves PostCSS integration to `@tailwindcss/postcss`; imports and vendor prefixing are handled by that plugin. The CSS-first theme preserves the existing border, background, foreground and primary colors, and explicit app/component source directories preserve the previous scanning scope. Authored styles follow generated utilities within the same cascade layer, retaining their previous specificity and ordering. The unused legacy configuration and separate Autoprefixer dependency are removed.

Preflight compatibility preserves the former default border color and the measured 42px native date-control size used in the remediation form. Native date-field internals vary across engines; preserving this outer size is not a claim of identical user-agent rendering. Existing placeholder, native input, button, focus and responsive layout styles are checked against the prior compiled CSS in local headless Chromium.

For a compiled-style comparison, install the unchanged qualification package with `npm ci` under `deploy/browser`, then run `node style-qualification.mjs <baseline.css> <migrated.css> <result.json>` from `frontend`. Set `ZG_STYLE_CHROME` to a local Chrome executable, or install the package's pinned Chromium binary. The script serves a CSS-only fixture on an OS-assigned loopback port, compares computed properties at desktop/mobile widths, records style differences, and closes its own browser/server. It does not exercise authentication or replace target-environment visual acceptance.

The standalone container now copies `public` with runtime ownership alongside standalone output and static CSS, ensuring the declared SVG favicon is included. Local standalone asset checks exercise this assembled layout; a local macOS build does not establish an Alpine build. Optional Linux musl x64/arm64 Oxide and Lightning CSS packages remain in the lock, and default optional-enabled `npm ci` must be preserved.

Tailwind v4 requires Safari 16.4+, Chrome 111+ and Firefox 128+, according to the official guide. Other browsers, the minimum supported engine versions, Alpine native execution and deployed identity-provider behavior remain environment-specific acceptance gates. No auth/session, CSP, backend or workflow behavior is changed by this migration.
