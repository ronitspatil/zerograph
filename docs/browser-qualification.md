# Disposable Chromium acceptance

The dedicated browser workflow builds the production-mode ZeroGraph stack and pinned disposable Keycloak fixture, then runs real Chromium using Playwright1.63.0 from an isolated qualification package. Product dependency locks remain independent. Each persona starts a fresh browser context and authenticates through the rendered provider form and frontend callback.

The generated fixture CA is installed in the isolated runner's system trust and task-private Chromium NSS database. Node explicitly trusts the same CA. Successful HTTPS navigation uses ordinary certificate verification; no certificate bypass flags or `ignoreHTTPSErrors` are used. Credentials and cookies remain in memory or the private generated fixture. Browser traces, screenshots, videos, HTML and raw errors are never recorded or uploaded. The only artifact is a fixed-label JSON outcome with counts; a regression verifies raw diagnostics cannot reach this reporter.

The browser cases cover protected initial navigation, production demo absence, actual login and callback navigation, hydrated graph/dashboard, Secure/HttpOnly/SameSite=Lax cookie attributes and DOM inaccessibility, UI snapshot ingestion, rendered canvas, keyboard node selection, graph filtering, simulator slider/results, viewer/analyst controls and authenticated API denial, a browser-generated cross-origin form logout denial, actual logout and expired encrypted-cookie replay. Normal successful UI phases require zero page/console errors; intentional denied requests are measured separately because browsers log their expected HTTP errors.

The cross-origin form uses the fixture API hostname, a different origin within the fixture site, proving the browser's generated Origin is rejected while the session remains usable. Actual provider redirect navigation and cookie attributes are qualified; a general matrix of third-party cookie restrictions or cross-site embedding is not claimed. Session expiry waits beyond the encrypted-token tolerance within75seconds. Logout clears the browser session; revocation of a copied, still-valid stateless cookie is not claimed.

Run only in a disposable Docker-enabled environment with the existing OIDC initializer/Compose/cleanup procedure, Node22, `npm ci` and `npx playwright install --with-deps chromium` under `deploy/browser`. Set `ZG_OIDC_FIXTURE_DIR`, `ZG_BROWSER_HOME`, `ZG_BROWSER_RESULT`, `NODE_EXTRA_CA_CERTS` and the browser binary path, provision explicit CA trust as in the workflow, then run `npm test`. The Docker project is `zerograph-browser-qualification-ci`; generated credential ownership remains under the existing OIDC fixture prefix so its cleanup protections are reused without alteration. Cleanup removes that isolated stack and ownership-validated credentials. Browser-home/NSS and binaries are ephemeral runner resources containing only fixture CA trust and disposable browser state.

This qualifies Chromium in isolated Linux CI. It does not qualify Firefox, Safari, mobile rendering, customer TLS/ingress, actual customer IdP claim mappings, MFA/conditional access, SCIM or live enterprise identity integration. Those remain target-environment acceptance gates tied to the intended release.
