# Kubernetes Helm qualification

The manually dispatched Kubernetes CI drill builds the application images from the checked-out release commit, loads them into a uniquely named disposable kind cluster, then installs the actual ZeroGraph chart with production settings and private generated Secret values. PostgreSQL, Redis and Memgraph are synthetic test fixtures with PVCs inside that cluster. No external Kubernetes context, public ingress, cloud account or operator database is used.

Run `python deploy/kubernetes.py --ci-disposable` only on an explicitly disposable CI runner (`CI=true`) with Docker, kind, kubectl, Helm and PyYAML installed. The runner creates a private temporary kubeconfig, verifies the exact context, loopback API endpoint and Docker node ownership label before Kubernetes/Helm access, and removes only its owned cluster. Existing clusters are never reused. Docker is restricted to the disposable Linux runner socket with empty private configuration; inherited Docker/Helm cluster, TLS, credential and release-storage overrides are stripped. Loopback HTTP probes bypass ambient proxies. Failures expose bounded operation labels; artifacts exclude kubeconfigs, Secret values, DSNs, manifests and pod logs. Generated credentials and private temporary files are removed when the process exits normally; a forcibly killed disposable runner requires runner-level destruction.

Assertions cover fresh SQL/graph migrations and migration hook success, actual Deployment readiness and Service endpoints, hardened application containers, startup/readiness/liveness probes, protected API and metrics, disabled demo sign-in, singleton scheduler, ConfigMap-triggered pod replacement during upgrade, and a coherent synthetic SQL revision pointer plus graph nodes/edges after application and PVC-backed store pod restarts, plus a synthetic Redis persistence marker. Uninstall and owned namespace/cluster deletion are checked. The sanitized JSON artifact records the source commit, image tags/runtime image IDs, Kubernetes version, hook execution and persistence proof.

This tests one-node ephemeral fixture persistence across pod restarts. It does not qualify managed storage recovery, node loss, scale, customer networking, ingress TLS, external identity sign-in or production capacity. The unreachable HTTPS issuer is deliberately a configuration fixture; authentication is never bypassed and no sign-in claim is made. The upgrade re-executes the current migration head with a configuration change; it does not qualify arbitrary historical database upgrades or mixed-version workers. Drain old workers before the documented incompatible ingestion migration.

Tool versions are fixed in CI: [kind v0.33.0 and its Kubernetes v1.36.4 node digest](https://github.com/kubernetes-sigs/kind/releases/tag/v0.33.0), kubectl v1.36.4, Helm v3.17.3. Downloaded kind/kubectl binaries are checksum-verified. The chart uses [Helm migration hooks](https://helm.sh/docs/topics/charts_hooks/); successful hook Jobs are deleted, and the drill inspects private Helm release state to verify each hook run. Hook ConfigMaps are explicitly cleaned because hook resources are not ordinary release-managed objects.

Before deployment, qualify the exact release on the authorized target Kubernetes version, registry, storage class, protected ingress/TLS and identity provider, including coordinated backup/restore and upgrade procedures. This CI artifact is installation evidence, not authorization to deploy or a production recovery guarantee.

The pinned Memgraph3.2 fixture requires its process UID to own the data directory, rather than merely having group write permission ([vendor source](https://github.com/memgraph/memgraph/blob/v3.2.0/src/storage/v2/durability/durability.cpp#L55)). Its isolated fixture init container runs with only CHOWN capability and changes only its mounted directory to UID/GID101; it does not recursively rewrite files or alter application/chart security. Bounded fixture-only failure logs are converted to permission/invalid-flag/OOM/no-space booleans; raw logs are never exported.

Runtime qualification remains incomplete: earlier kind runs observed Memgraph exit139 before application installation. The ownership preparation is locally tested and source-informed, but its effect on that observed crash has not been verified. Further Actions runs are halted under the operator's CI minutes budget; local lint/unit/render checks do not replace runtime evidence.

The expensive workflow is manual-only, has a single concurrency group and a 25-minute timeout. A push or pull request does not start this drill. Dispatching it requires an explicit operator decision; no new run has been started since the CI budget halt.
