# Bounded graph exploration

The dashboard can request a bounded view of the current tenant revision instead of loading every entity into the browser. `GET /api/v1/graph/explore` returns the existing revision/nodes/edges/warnings shape plus `view` metadata. Without `root_id` it selects nodes in ID order; with an exact root it returns that root and a bounded set of one-hop neighbors in both directions, including annotation edges. Edges are returned only when both endpoints are visible, in deterministic edge-ID order.

`node_limit` defaults to 250 and accepts 1–500; `edge_limit` defaults to 1,000 and accepts 1–2,000. The metadata reports these limits, mode/root, total current-revision node/edge counts and `truncated`. Any omitted nodes or edges marks the view partial, including a neighborhood that intentionally excludes unrelated graph regions. Counts come from database aggregates, rather than a full payload snapshot. These aggregates and deterministic neighborhood sorting may still scan the scoped graph; bounded response size does not imply constant query cost.

`GET /api/v1/graph/search?q=...` searches the whole current tenant revision by case-insensitive ID/name substring. Queries are trimmed and must contain 1–128 characters. `limit` defaults to 25 and accepts 1–50; a single sentinel row establishes `has_more`. IDs are sorted, and selecting a result can request its neighborhood. Search does not depend on the visible slice.

Both endpoints accept an expected `revision`; a changed pointer returns 409 so clients can reset before mixing views. A missing root returns 404. An empty tenant returns revision `""` and zero counts; a nonempty publication pointer whose graph metadata is missing returns retryable 503 instead of claiming a complete empty graph. Viewer access is sufficient; tenant scope comes exclusively from the verified actor. The SQL revision pointer is held with a shared lock through graph query/materialization, using the existing five-second lock timeout and publisher/retention coordination. Cypher uses fixed, parameterized, timeout-bound queries, no variable-length traversal, and limits all entity/relationship payload rows; endpoints and relationships are scoped to tenant and revision and relationship types are whitelisted.

This slice changes visualization retrieval only. Existing publication limits remain 5,000 nodes/20,000 edges per snapshot; the legacy `/graph`, overview/findings and blast-radius simulation still materialize the full snapshot. Visible nodes cannot establish complete effective access or blast radius. Filters/exports apply to the visible view, and analyses may include affected nodes outside it. Large-graph ingestion, cached aggregates, permission-analysis scaling and global clustering remain separate work; no 100,000-node or million-node capacity is qualified.

Memory/API and Cypher query-contract tests cover bounds, tenant/revision isolation, dense hubs, both directions, annotations, visible endpoints, search sentinels and missing published metadata. Real Memgraph/Neo4j integration checks are opt-in via the existing `ZG_INTEGRATION_GRAPH` environment and deliberately insert malformed cross-tenant/revision/type relationships. They require disposable graph services; local query-contract tests do not replace that runtime evidence.
